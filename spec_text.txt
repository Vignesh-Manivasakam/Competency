MVP Strategy and Scope
1.1 Philosophy: Maximised MVP
A Maximised MVP is not a toy prototype.
It is the smallest surface area that
delivers the full core value loop end-to-end, with a technical foundation that
cleanly scales into the 22-agent full system without rewrites.
✓The Core Loop That Must Work in MVP
Manager denes competency →AI decomposes to skill graph →Man-
ager validates →Employee baseline assessed →Adaptive learning session
runs →Mastery detected →Competency matrix updated
1.2 What Is Included in MVP
 Competency creation, AI decomposition to skill DAG, manager validation
 Employee onboarding and multi-modal baseline assessment (quiz + conversational)
 Adaptive learning session with embedded real-time assessment
 Mastery determination and competency matrix update
 Manager dashboard (competency structure + team progress)
 Employee portal (learning sessions, progress view)
 9-agent eet (collapsed from 22; merged related agents)
 Full observability via LangSmith
1.3 What Is Deferred to Phase 2
 Voice-based assessment (Voice Evaluation Agent)
 Mindmap and video content generation
 Meta-learning agents (self-improvement loop)
 Kafka event streaming (replaced by direct async calls in MVP)
 Multi-tenant enterprise isolation (single-tenant MVP)
 Spaced repetition scheduler (manual trigger in MVP)
 Organisational Intelligence Dashboard (aggregated analytics)

Memory Layer Architecture
5.1 Four-Tier Memory Model
Tier 1  Agent Working Memory (In-Process)
Python dicts within a single LangGraph node invocation. TTL = sin-
gle LLM call. Not persisted.
Tier 2  Session State (Redis)
Full session context: messages, scores, module pointer, tutor memory.
TTL = 24h. Key: session:{id}:state
Tier 3  Persistent Learning State (PostgreSQL)
Employee prociency scores, assessment history, mastery decisions,
competency matrix. Permanent, append-only for mastery log.
Tier 4  Knowledge Graph Memory (Neo4j + pgvector)
Skill DAG, prerequisites, content embeddings. Shared across all em-
ployees. Updated by manager validation events.
